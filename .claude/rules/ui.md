# UI / UX Guideline（要約）

方針：UIは「要素を増やさず、迷わせず、失敗させない」を最優先にする。

## 上位10（常時守る）
1. シンプルにする（要素を増やさない）
2. 簡単にする（手順を減らす）
3. メンタルモデルに合わせる
4. シグニファイア（押せそう/押せなさそうを明確に）
5. 一貫性（同じものは同じ表現・挙動）
6. ユーザーの言葉を使う（専門用語を避ける）
7. ユーザーの記憶に頼らない（その場で参照できる）
8. エラーを回避する（起きない設計 + 建設的メッセージ）
9. 可逆性（戻せる/取り消せる）
10. メジャータスク最適化（80%に合わせる）

## UI 変更時の基本（実装前に決める）
- 先に state を列挙する：idle / loading / loaded / empty / error（必要最小でOK）
- エラーは「次に何をすればいいか」が分かる文言にする（専門用語を避ける）
- 入力がある場合はバリデーションと建設的メッセージを用意する

## UI 変更の Done（最小）
- 主要 state（loading/empty/error を含む）を最低1回確認する
- 文言を見直す（ユーザーの言葉・曖昧語なし・一貫性）
- 取り消し/戻るなどの可逆性を壊していない
- アクセシビリティ最低限：タップ領域/ラベル（できる範囲で）
